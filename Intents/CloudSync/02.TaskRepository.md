# 2. TaskRepository

**Goal**: A small module that owns every Firestore read/write for tasks, so `app.js` never talks to Firestore directly.
**Est.**: 1h
**Dependencies**: FirestoreSetup

## Steps
- [x] Create `src/js/tasks-repo.js` exporting:
  - `subscribeToTasks(uid, onChange)` — `onSnapshot` on `users/{uid}/tasks`, calls `onChange(tasksArray)` on every update (including the SDK's instant local-cache echo), returns an unsubscribe function
  - `addTask(uid, { title, time, notes, date })` — `addDoc`
  - `updateTask(uid, taskId, updates)` — `updateDoc`
  - `deleteTask(uid, taskId)` — `deleteDoc`
- [x] Each write function returns the underlying promise so callers can catch failures (used in intent 5 for error states)

## Definition of Done
- [x] `app.js` (intent 3) will not need to import anything from `firebase.js` directly — only from `tasks-repo.js`
- [x] All four functions are pure passthroughs to Firestore with no UI/DOM knowledge, so they're reusable and testable in isolation

## Outcome (fill after Iterate)
- **Actual Time**:
- **Result**: `tasks-repo.js` added with the four functions plus an `onError` parameter on `subscribeToTasks` (needed by intent 5's error banner — snapshot listeners report errors via callback, not a rejected promise). `migrateLocalTasksIfNeeded` is deliberately not here yet; it's intent 4's job and will extend this same file.
- **Follow-ups**: None.
