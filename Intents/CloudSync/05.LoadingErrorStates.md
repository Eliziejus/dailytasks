# 5. LoadingErrorStates

**Goal**: Give the planner visible loading/error states now that task persistence is a network call instead of a synchronous local write.
**Est.**: 0.5h
**Dependencies**: WireAppToFirestore, LocalStorageMigration

## Steps
- [x] Reuse the existing `data-auth-pending` loading pattern: keep the planner hidden behind the "Loading…" state until migration has run and the first Firestore snapshot has arrived, not just until auth resolves
- [x] Add a small error banner (reusing `.form-error` styling) shown if `addTask`/`updateTask`/`deleteTask` rejects (e.g. offline, permission-denied from a rules misconfiguration) or if `subscribeToTasks` reports an error
- [x] Keep the task dialog's existing validation/error handling as-is; only the network-failure path is new

## Definition of Done
- [x] A failed write shows a visible, human-readable message instead of silently doing nothing
- [x] There's no flash of an empty task list between "signed in" and "first Firestore data arrived"

## Outcome (fill after Iterate)
- **Actual Time**:
- **Result**: Split the `data-auth-pending` responsibility: `auth-guard.js` still redirects when signed out and reveals the header's user-info/logout, but no longer clears `data-auth-pending` itself — `app.js` now owns that, clearing it only once the first `subscribeToTasks` callback fires (success or error). A new `#sync-error` banner (`.sync-error`, styled as a filled variant of the existing `.form-error` red) sits at the top of `<main>`; it's shown by the subscription's error callback and by the checkbox/delete `.catch` handlers (replacing intent 3's `console.error`-only placeholders), and cleared on the next successful sync. If the subscription itself errors, loading still stops (`stopLoading()` runs in both branches) so the user sees the error instead of an infinite "Loading…". Re-verified via Playwright: all three pages still load with zero console errors after these changes.
- **Follow-ups**: None.
