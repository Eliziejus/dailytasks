# 5. LoadingErrorStates

**Goal**: Give the planner visible loading/error states now that task persistence is a network call instead of a synchronous local write.
**Est.**: 0.5h
**Dependencies**: WireAppToFirestore, LocalStorageMigration

## Steps
- [ ] Reuse the existing `data-auth-pending` loading pattern: keep the planner hidden behind the "Loading…" state until migration has run and the first Firestore snapshot has arrived, not just until auth resolves
- [ ] Add a small error banner (reusing `.form-error` styling) shown if `addTask`/`updateTask`/`deleteTask` rejects (e.g. offline, permission-denied from a rules misconfiguration) or if `subscribeToTasks` reports an error
- [ ] Keep the task dialog's existing validation/error handling as-is; only the network-failure path is new

## Definition of Done
- [ ] A failed write shows a visible, human-readable message instead of silently doing nothing
- [ ] There's no flash of an empty task list between "signed in" and "first Firestore data arrived"
