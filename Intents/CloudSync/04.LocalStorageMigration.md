# 4. LocalStorageMigration

**Goal**: A user who already has tasks in this browser's `localStorage` from before CloudSync should see them appear in their account automatically, exactly once.
**Est.**: 1h
**Dependencies**: WireAppToFirestore

## Steps
- [ ] Add `migrateLocalTasksIfNeeded(uid)` to `tasks-repo.js`: read `users/{uid}`; if the doc doesn't exist or `migratedFromLocalStorage` is not `true`, read the old `dailyPlanner.tasksByDate` `localStorage` key, `writeBatch` every task found into `users/{uid}/tasks`, then `setDoc(users/{uid}, { migratedFromLocalStorage: true }, { merge: true })`
- [ ] Mark as migrated even when `localStorage` was empty, so the check only ever runs the batch write once per account, not once per login
- [ ] Call this once, right after auth confirms a user and before (or racing with) the first `subscribeToTasks` call, in `app.js`
- [ ] Do not delete the `localStorage` data — leave it in place as an inert backup; it's simply no longer read after migration

## Definition of Done
- [ ] A browser with existing `dailyPlanner.tasksByDate` data sees those tasks appear in Firestore (and thus in the UI) the first time that browser logs into an account
- [ ] Logging in again afterward does not duplicate the migrated tasks
- [ ] A brand-new account with no prior `localStorage` data is unaffected (no errors, no phantom writes beyond the `migratedFromLocalStorage` flag)
