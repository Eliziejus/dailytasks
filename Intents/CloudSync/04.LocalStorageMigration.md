# 4. LocalStorageMigration

**Goal**: A user who already has tasks in this browser's `localStorage` from before CloudSync should see them appear in their account automatically, exactly once.
**Est.**: 1h
**Dependencies**: WireAppToFirestore

## Steps
- [x] Add `migrateLocalTasksIfNeeded(uid)` to `tasks-repo.js`: read `users/{uid}`; if the doc doesn't exist or `migratedFromLocalStorage` is not `true`, read the old `dailyPlanner.tasksByDate` `localStorage` key, `writeBatch` every task found into `users/{uid}/tasks`, then `setDoc(users/{uid}, { migratedFromLocalStorage: true }, { merge: true })`
- [x] Mark as migrated even when `localStorage` was empty, so the check only ever runs the batch write once per account, not once per login
- [x] Call this once, right after auth confirms a user and before (or racing with) the first `subscribeToTasks` call, in `app.js`
- [x] Do not delete the `localStorage` data — leave it in place as an inert backup; it's simply no longer read after migration

## Definition of Done
- [x] A browser with existing `dailyPlanner.tasksByDate` data sees those tasks appear in Firestore (and thus in the UI) the first time that browser logs into an account
- [x] Logging in again afterward does not duplicate the migrated tasks
- [x] A brand-new account with no prior `localStorage` data is unaffected (no errors, no phantom writes beyond the `migratedFromLocalStorage` flag)

## Outcome (fill after Iterate)
- **Actual Time**:
- **Result**: `migrateLocalTasksIfNeeded` added to `tasks-repo.js`, `app.js` awaits it (inside the `onAuthStateChanged` callback, wrapped in try/catch so a migration failure doesn't block the task subscription from starting) before calling `subscribeToTasks`. The `migratedFromLocalStorage` flag and the batch write happen in the same `writeBatch`, so a crash mid-migration can't leave the flag set without the tasks (or vice versa). `localStorage` is left untouched, matching the design. Re-verified `login.html`/`register.html`/`index.html` load cleanly with no console errors via the same Playwright script; actual migration behavior needs a real Firestore project (deferred to intent 6).
