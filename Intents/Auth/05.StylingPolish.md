# 5. StylingPolish

**Goal**: Make login/register/logout visually consistent with the existing planner UI, with clear error/loading states.
**Est.**: 1h
**Dependencies**: LoginPage, RegisterPage, AuthGuard

## Steps
- [x] Extend `src/css/styles.css` (or add `src/css/auth.css`, linked from `login.html`/`register.html`) reusing existing tokens/classes (buttons, inputs, error text) rather than inventing a parallel style language
- [x] Style the auth forms' error state to match `#task-form-error` conventions already in the app
- [x] Style the header's user-email + logout button consistently with `.app-header`
- [x] Verify responsive behavior on narrow viewports, matching the responsive work already done for the planner (StylingPolish intent 7 of DailyPlanner)

## Definition of Done
- [x] Login, register, and the gated planner all look like one app, not three
- [x] Forms are usable and legible at mobile widths
- [x] Errors and loading states are visually distinct and accessible (not color-only)

## Outcome (fill after Iterate)
- **Actual Time**:
- **Result**: Added `role="alert"` to the login/register error paragraphs so screen readers announce them (not just a color/visibility change). Fixed a responsive overlap: `.user-info` was absolutely positioned in the header and would collide with the "Daily Planner" title on narrow screens — it now falls back to `position: static` and stacks below the title under the existing 480px breakpoint. Added a matching mobile breakpoint to `auth.css` for form padding. Verified via Playwright against a local static server (`python -m http.server`) serving `src/`: `login.html` and `register.html` render styled and error-free at both desktop and 375px mobile widths, and `index.html` correctly redirects unauthenticated visitors to `login.html` with zero console errors. Screenshots confirm visual consistency with the planner's existing look.
- **Follow-ups**: None.
