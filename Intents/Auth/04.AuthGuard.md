# 4. AuthGuard

**Goal**: Gate the existing planner (`index.html`) behind auth, and let a signed-in user log out.
**Est.**: 1h
**Dependencies**: FirebaseSetup, LoginPage

## Steps
- [x] In `index.html` (or a small new `src/js/auth-guard.js` imported first), subscribe to `onAuthStateChanged`; if signed out, redirect to `login.html` before the planner UI renders
- [x] While the auth state is still resolving on first load, show a brief loading state instead of a flash of the planner UI
- [x] Add a "Log out" button to the app header, wired to `signOut`, redirecting to `login.html` afterward
- [x] Show the signed-in user's email somewhere in the header

## Definition of Done
- [x] Visiting `index.html` while signed out redirects to `login.html`
- [x] Visiting `index.html` while signed in shows the planner, unchanged from before this feature (`app.js` task logic untouched)
- [x] Logging out redirects to `login.html` and a subsequent visit to `index.html` redirects again (no stale session)

## Outcome (fill after Iterate)
- **Actual Time**:
- **Result**: Added `js/auth-guard.js` (ES module) plus a `data-auth-pending` attribute on `<body>` that CSS uses to hide `<main>` and show a "Loading…" message until `onAuthStateChanged` resolves — avoids a flash of planner content, and works regardless of the relative execution order between the module script and `app.js`'s classic script. `app.js` itself is untouched. Header gained a `#user-info` block (email + logout button), populated by the guard once a user is confirmed. Not yet testable end-to-end — needs real Firebase config (intent 6).
- **Follow-ups**: None beyond the deferred live-project verification.
